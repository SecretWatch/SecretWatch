# SecretWatch

SecretWatch는 개발자 PC에서 파일 변경을 실시간으로 감지하고, 변경된 코드와 설정 파일을 대상으로 Secret, 개인정보, 취약 암호화 알고리즘 등의 민감정보를 탐지하는 로컬 기반 DevSecOps 보안 도구입니다.

정규식과 엔트로피를 활용한 1차 탐지 결과를 Jev 결정 모델로 분류하고, 실제 위험 가능성이 높은 항목에 위험도를 부여합니다. 최종 탐지 결과는 원문을 마스킹한 뒤 개발자 PC에 저장하며, 로컬 EXE GUI에서 대시보드 형태로 확인할 수 있습니다.

## 핵심 특징

- 개발자 PC에서 파일 저장 및 수정 이벤트 실시간 감지
- Git Diff 기반 변경 코드 Hunk 증분 스캔
- 정규식과 엔트로피 기반 1차 탐지
- Secret, PII, 취약 암호화, 설정 파일 및 로그 탐지
- Jev 결정 모델을 이용한 문맥 기반 분류
- `likely_real`, `likely_test`, `placeholder` 분류
- `likely_real` 결과에 대한 `High`, `Medium`, `Low` 위험도 산정
- Secret 및 PII 원문 마스킹
- 탐지 결과 로컬 저장
- 로컬 EXE GUI 기반 대시보드 제공
- 중앙 서버 및 외부 데이터 전송 없이 로컬 환경에서 동작

## 프로젝트 배경

소프트웨어 개발 과정에서는 API Key, Password, Access Token과 같은 인증정보뿐만 아니라 주민등록번호, 이메일, 전화번호와 같은 개인정보가 소스코드, 환경 설정 파일, 런타임 로그, 빌드 로그 등에 포함될 수 있습니다.

기존의 단순 패턴 기반 탐지 방식에는 다음과 같은 한계가 있습니다.

- 테스트 데이터와 실제 운영 Secret을 구분하기 어려움
- 예시 값과 Placeholder까지 탐지하여 오탐이 증가함
- 고정 접두어가 없는 커스텀 Secret을 탐지하기 어려움
- 파일 전체를 반복 검사하여 CPU 및 I/O 부하가 발생함
- Commit 또는 Push 이후 탐지되어 Git History에 Secret이 남을 수 있음
- `.env`, `.yaml`, `.json`, 빌드 로그 등 비구조화 영역의 탐지가 부족함

SecretWatch는 파일 전체가 아닌 실제 변경 영역을 검사하고, Jev 기반 문맥 분류를 적용하여 오탐을 줄이는 것을 목표로 합니다.

## 전체 처리 흐름

### 1. 파일 변경 감지

개발자가 소스코드 또는 설정 파일을 저장하거나 수정하면 운영체제의 파일 시스템 이벤트를 통해 변경을 감지합니다.

- Windows: USN Record 기반 감지
- Linux 및 WSL2: inotify 기반 감지
- 감지된 변경 파일을 Event Queue에 등록

### 2. 변경 코드 추출

변경된 파일이 Git 저장소에 포함되어 있는 경우 Git Diff를 수행합니다.

- 실제로 수정된 코드 Hunk 추출
- 변경된 줄과 주변 문맥 추출
- 파일 전체를 반복 검사하지 않는 증분 스캔 방식 적용
- Git 저장소 외부 파일은 필요에 따라 파일 전체 검사

### 3. 1차 탐지

추출된 코드 Hunk와 파일 문맥을 대상으로 정규식과 엔트로피 분석을 수행합니다.

1차 탐지 대상은 다음과 같습니다.

- Secret 및 인증정보
- 개인정보
- 취약 암호화 알고리즘
- 비구조화 설정 파일
- 빌드 및 런타임 로그

1차 탐지 결과에는 다음 정보가 포함될 수 있습니다.

- 탐지된 후보 값
- 파일 경로
- 줄 번호
- 변수명
- 주변 소스코드
- 탐지 규칙
- 엔트로피 점수
- 탐지 유형

### 4. Jev 문맥 분류

1차 탐지 후보에 파일 경로, 변수명, 주변 코드 등의 문맥을 결합하여 Jev 결정 모델에 전달합니다.

Jev는 탐지 후보를 다음 세 가지로 분류합니다.

| 분류 | 설명 |
|---|---|
| `likely_real` | 실제 운영 환경에서 사용되는 Secret 또는 민감정보일 가능성이 높은 데이터 |
| `likely_test` | 테스트 코드 또는 검증 목적으로 사용되는 데이터 |
| `placeholder` | 예시, 샘플, 더미 값으로 사용되는 데이터 |

현재 설계에서는 `likely_real`로 분류된 항목만 위험도 산정 대상으로 처리합니다.

`likely_test`와 `placeholder`의 저장 및 GUI 표시 여부는 구현 정책에 따라 별도로 결정합니다.

### 5. 위험도 분류

`likely_real`로 분류된 Finding은 탐지 유형, 문맥, 노출 영향 등을 기준으로 위험도를 분류합니다.

| 위험도 | 설명 |
|---|---|
| `High` | 즉시 대응이 필요한 고위험 Secret 또는 민감정보 |
| `Medium` | 실제 위험 가능성이 있으나 추가 확인이 필요한 항목 |
| `Low` | 위험 영향이 비교적 낮거나 제한적인 항목 |

위험도 기준은 프로젝트 정책과 탐지 규칙에 따라 세부 조정할 수 있습니다.

### 6. 마스킹 및 대시보드 데이터 구성

위험도 분류가 완료된 Finding은 로컬 저장 전에 마스킹합니다.

예시:

- 원문: `sk_live_51ABCDEF123456`
- 저장 값: `sk_live_****3456`

대시보드 데이터에는 다음 정보가 포함될 수 있습니다.

- 파일 경로
- 줄 번호
- 탐지 유형
- Jev 분류 결과
- 위험도
- 마스킹된 값
- 탐지 시간
- 탐지 규칙
- 조치 상태
- 문맥 요약

Secret 또는 PII 원문은 마스킹 처리 후 메모리에서 제거하며, 디스크에는 저장하지 않는 것을 원칙으로 합니다.

### 7. 로컬 저장

마스킹된 Finding은 개발자 PC의 로컬 Findings Store에 저장합니다.

현재 저장 방식은 구현 단계에서 결정할 수 있습니다.

- JSON
- NDJSON
- SQLite
- 기타 로컬 저장 형식

저장소에는 원문 Secret이나 PII를 저장하지 않고, 마스킹된 결과와 탐지 메타데이터만 저장합니다.

### 8. EXE GUI 대시보드

로컬 EXE GUI는 Findings Store를 읽어 대시보드를 구성합니다.

GUI에서 제공할 수 있는 기능은 다음과 같습니다.

- 전체 Finding 목록 조회
- 위험도별 필터
- 탐지 유형별 필터
- 파일 경로 및 줄 번호 확인
- 마스킹된 탐지 값 확인
- 상세 문맥 확인
- 조치 상태 관리
- 로컬 실시간 알림
- 탐지 내역 검색

## 탐지 범위

### Secret 및 인증정보

- API Key
- Access Token
- GitHub Token
- OpenAI API Key
- AWS Access Key
- Stripe Secret Key
- DB Password
- Connection String
- SSH Private Key
- X.509 인증서
- `SECRET_TOKEN`
- 고정 패턴이 없는 커스텀 Secret

### 개인정보

- 주민등록번호
- 이메일
- 전화번호
- 계좌번호
- 기타 형식 기반 개인정보

주민등록번호와 같은 데이터는 단순 정규식뿐만 아니라 자릿수 및 유효성 검증 알고리즘을 함께 사용할 수 있습니다.

### 취약 암호화 알고리즘

- MD5
- SHA-1
- DES
- RC4
- ECB Mode
- 기타 사용을 지양해야 하는 암호화 알고리즘

### 비구조화 파일 및 로그

- `.env`
- `.yaml`
- `.yml`
- `.json`
- 설정 파일
- 런타임 로그
- CI/CD 빌드 로그
- stdout 및 stderr 로그

## 핵심 모듈

| 모듈 | 역할 |
|---|---|
| OS Change Engine | 운영체제의 파일 저장 및 수정 이벤트 감지 |
| Event Queue | 변경된 파일 이벤트 관리 |
| Git Diff Hunk Extractor | 실제 변경된 코드 영역과 주변 문맥 추출 |
| First-pass Detection Engine | 정규식과 엔트로피 기반 후보 탐지 |
| Jev Classification Engine | `likely_real`, `likely_test`, `placeholder` 문맥 분류 |
| Risk Classification Engine | `likely_real` 결과를 `High`, `Medium`, `Low`로 분류 |
| Data Sanitizer | Secret 및 PII 원문 마스킹 |
| Finding Serializer | 탐지 결과를 로컬 저장 형식으로 변환 |
| Local Findings Store | 마스킹된 탐지 결과 로컬 저장 |
| EXE GUI Dashboard | 로컬 탐지 결과 조회 및 관리 |

## 로컬 보안 원칙

SecretWatch는 다음 원칙을 기준으로 동작합니다.

1. 모든 탐지와 분류는 개발자 PC 내부에서 수행합니다.
2. 중앙 서버로 소스코드 또는 탐지 결과를 전송하지 않습니다.
3. 네트워크 전송 없이 로컬 환경에서 동작합니다.
4. Secret과 PII 원문은 디스크에 저장하지 않습니다.
5. 탐지 결과는 저장 전에 마스킹합니다.
6. GUI는 마스킹된 로컬 Findings Store만 읽습니다.
7. 파일 전체가 아닌 변경된 영역을 우선 검사합니다.
8. Jev 결정 모델은 On-Device 방식으로 실행합니다.

## 프로젝트 목표

SecretWatch의 최종 목표는 개발자가 코드를 저장하는 순간 민감정보를 탐지하고, 실제 위험과 테스트 데이터를 구분하여 Commit 또는 Push 이전에 빠르게 조치할 수 있도록 지원하는 것입니다.

이를 통해 다음 효과를 기대합니다.

- Secret의 Git History 잔존 방지
- 테스트 데이터로 인한 오탐 감소
- 개발자의 경고 피로도 감소
- 소스코드 외 설정 파일과 로그까지 탐지 범위 확장
- 외부 전송 없는 On-Device 데이터 보호
- 변경 영역 중심 검사로 시스템 부하 최소화
